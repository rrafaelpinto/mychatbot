# UI/UX improvement workflow

## Objective

Make ResumeBot an effective recruiter-facing engineering portfolio. Lead with the candidate's published experience and allow direct questions about Python, Django, Django REST Framework, PostgreSQL, API design, and applied AI.

The React frontend uses the backend's versioned DRF API. UI work must not change publication, privacy, permission, rate limiting, conversation history, or paid-provider policies.

## Skills

Invoke `ui-ux-review` for every user-facing change. Use `ui-ux-pro-max` for a focused review of a layout, accessibility, navigation, or interaction decision. Use `ui-styling` for implementation details. The scoped adaptations are in `.agents/skills/`. They adapt the workflow used in Talent Pool without copying its entire third-party design catalog.

Read `AGENTS.md`, `docs/design/DESIGN_SYSTEM.md`, and the affected React components first.

## Review loop

1. Diagnose the actual route and state; describe usability and accessibility findings by severity.
2. Decide which visual hierarchy, copy, or interaction should change and why.
3. Implement without changing backend business rules.
4. Run `npm --prefix frontend run build`, `npm --prefix frontend test`, and `npm --prefix frontend run test:e2e`. Inspect desktop and mobile screenshots, not just passing assertions.
5. Fix the concrete visual defects and repeat, for a maximum of three screenshot review cycles.

### Review surface

- Public landing: recruiter discovers the candidate and direct route to chat.
- Public profile: approved summary and facts, contact if published, Agent CTA.
- Candidate Agent: genuine conversation history, supporting evidence, suggested questions, guest verification/limits.
- Owner dashboard: readable controls, authenticated behavior, responsive forms.

Test desktop 1440px, tablet 768px, mobile 390px, and minimum mobile 320px where appropriate. Include keyboard, visible focus, semantic landmarks, overflow, and contrast checks. Preserve reduced-motion support.

## README screenshots

The versioned images live in `docs/assets/` and are generated by `frontend/e2e/readme-screenshots.spec.ts`. It uses deterministic, publication-safe professional facts and first-person answers, with network responses isolated from paid AI calls. The resulting images represent actual React UI rendering.

The `Capture README screenshots` GitHub Actions workflow updates images on `ui/*` branches after source changes. Inspect the output images and compare them with the frontend before merging. The screenshot test is not a substitute for a real browser review of functional behavior.

Record in the PR the pages/viewports inspected, commands and results, findings corrected, iteration count, and any remaining limitations. Never claim to have visually inspected an image that was not opened.
